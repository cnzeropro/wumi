## 2. 调研结论（2026-09，详见对话存档）

- **市场空位**："中文 + 免费 + 数据存用户自己的云 + Material 3" 组合无强势玩家。钱迹（¥128 买断，官方明确拒绝第三方云）、一羽（WebDAV 但云同步卖 ¥98）、海外产品（不支持 WebDAV / 中文弱）、蜜蜂记账（2025.10，MIT 开源，最接近的先行者但功能不完整）。
- **可借鉴的已验证模型**：蜜蜂记账的 UUID + updatedAt 增量同步 + 软删除在 WebDAV 上可行。
- **同步后端排序**（大陆、单用户、双设备场景）：
  1. 坚果云 WebDAV（免费 1GB 上传/月 vs 年数据量 ~2MB；600 请求/30min 限流；国内直连快且稳）
  2. 本地 + 加密导出（零依赖兜底）
  3. Cloudflare Workers + D1（需域名 ¥20/年 + 自写 API，进阶选项）
  - GitHub 私仓：免费无限 + 天然版本历史，但大陆直连时通时断（api.github.com DNS 污染且域名写死）、Contents API 读改写有覆盖/限流坑、PAT 等同密码。**结论：只作为路线图上的可插拔后端，不做唯一后端。**
  - Firebase：大陆完全不可用，排除。Supabase：7 天不活跃暂停 + 部分域名被阻，排除。

## 4. 架构总览

```
┌────────────────────────────── Android App ──────────────────────────────┐
│  ui/        Compose 界面（明细 · 图表 · 记一笔 · 预算 · 我的）             │
│  data/      Room 实体 · DAO · Repository（唯一写入口，带 outbox）         │
│  sync/      同步引擎（LWW 合并）· SyncBackend 接口 · webdav/ 实现         │
│  crypto/    AES-256-GCM 信封加密 · PBKDF2 密钥派生                        │
│  di/        Hilt 模块                                                     │
└──────────────────────────────────────────────────────────────────────────┘
              │                                    │
              ▼                                    ▼
      本地 Room（唯一真相源）              SyncBackend 实现（可插拔）
      每日滚动备份 7 份                    ├─ WebDAV（坚果云，首发）
                                          ├─ Git/GitHub（路线图）
                                          └─ S3 兼容（路线图）
```

**架构第一原则：本地 Room 是唯一真相源，云端只是复制物。** 未配置任何同步后端时 App 功能 100% 完整可用；同步是附加能力而非依赖项。

技术选型：Navigation Compose（单 Activity）、MVVM + StateFlow、Room、Hilt、OkHttp 自封装 WebDAV 客户端（~200 行，避免停更第三方库）、Vico 图表、WorkManager 后台调度。

## 5. 数据模型

### 5.1 同步基因（每个业务实体必有）

| 字段 | 类型 | 作用 |
|------|------|------|
| `id` | UUIDv7（字符串） | 客户端生成，时间有序，离线可造新记录 |
| `createdAt` | Instant | 创建时间 |
| `updatedAt` | Instant | LWW 合并依据 |
| `deletedAt` | Instant? | 软删除墓碑，跨设备传播删除 |
| `deviceId` | String | 最后修改者；LWW 平局决胜；预留家庭共享 |

### 5.2 实体清单

```
Account        账户：名称、emoji、币种、期初余额(Long 分)、类型(现金/银行卡/支付宝/
               微信/信用卡)、信用卡额度与账单日、是否计入净资产、排序
Category       二级分类：parentId 自引用、类型(支出/收入)、emoji、排序、归档时间
               (归档不删除，历史报表保留)
Transaction    交易：类型(支出/收入/转账)、金额(原币种最小单位 Long)、币种(ISO 4217)、
               汇率快照(Decimal 字符串)、本位币金额(冗余 Long，统计用)、账户、
               对方账户(仅转账)、分类、日期(LocalDate)、备注、来源(手动/导入/周期)、
               周期规则 id?
Budget         预算：总预算或分类预算、月度金额(本位币)
RecurringRule  周期规则：内嵌模板(金额/分类/账户/备注)、频率(日/周/月/年+间隔)、
               nextRunAt、启用状态；错过多期最多补 3 期
CurrencyInfo   币种：代码、名称、符号、小数位(日元 0/第纳尔 3)、对本位币汇率(手动维护)、
               汇率更新时间
Setting        KV 设置表
OutboxEntry    待推送队列：实体类型、记录 id、入队时间（与业务表同事务写入）
```

### 5.3 金额铁律

- 所有金额 `Long` 存最小单位（分/cent），显示层才做千分位与币种符号格式化——杜绝浮点误差。
- 汇率存字符串（BigDecimal 解析）。
- 多币种：记账时锁定当日汇率快照存入交易；统计用本位币冗余字段；历史账单不随汇率波动重算。
- 输入层限制单笔金额 ≤ 9 位数（Long 上限约 9 千万亿元，溢出无虞）。

## 6. 同步引擎

### 6.1 云端仓库布局

```
/wumi/
  manifest.json.enc        # 仓库指针：repoVersion、设备注册表、ops 游标、最新快照名、口令校验值
  ops/
    0001.json.enc          # 变更批次：每片 ≤500 条记录
    0002.json.enc
  snapshots/
    snap-2026W37.json.enc  # 全量快照（分片过多时压实）
```

分片序号递增（不用日期命名，避免时钟偏移）；水位记录在 manifest。

### 6.2 加密

- 同步口令 → PBKDF2-HMAC-SHA256（210,000 迭代）→ 256-bit 主密钥 KEK。
- 每文件随机数据密钥 DEK 加密内容；KEK 包 DEK（**信封加密**，改口令不用重加密全部文件）。
- 文件格式：`{明文头: 版本/算法/salt/iv} + {密文体}`；云端只见密文。
- 新设备凭口令 + manifest 校验值（不同 salt 二次派生）验证，无需转移密钥文件。

### 6.3 同步会话流程

```
① GET manifest (ETag) ──远端没变且本地无待推→ 结束
② 拉本地水位之后的 ops 分片 → 逐条 LWW 合并进本地 Room
③ 推本地 outbox → 新 ops 分片（PUT，If-Match/ETag 乐观锁）
④ PUT manifest；ETag 冲突 → 拉取合并重推（最多 3 轮，防活锁）
⑤ 分片超阈值 → 写全量快照 + 清理旧分片（保留最近 K 片）
⑥ 更新本地水位
```

- **outbox 模式**：Repository 写业务表与写 outbox 在同一 Room 事务——记了账就一定在队列里，崩溃不丢。
- **LWW 规则**：`updatedAt` 新者胜；同刻（含 30 秒内时钟模糊区）以 `deviceId` 字典序决胜。确定性保证：两台设备任意顺序合并相同变更集，结果必然一致。
- **时钟偏移校正**：每次同步会话与远端对时，记录本机偏移量，合并前校正 `updatedAt`。
- **墓碑治理**：删除传播后保留 30 天（防复活）；manifest 中所有已注册设备水位都越过该墓碑后物理清除。
- **触发时机**：启动/回前台（防抖 5s）、本地写入后 30s 防抖、手动下拉刷新、WorkManager 每 6 小时（充电+联网约束）。
- **限流预算**：一次同步 3-8 个请求 vs 坚果云 600 次/30min，余量 20 倍以上。

### 6.4 可换云（迁移性保证）

```
interface SyncBackend {
    suspend fun get(path: String): FileWithEtag?
    suspend fun put(path: String, bytes: ByteArray, ifMatch: Etag?): Etag
    suspend fun list(dir: String): List<FileEntry>
    suspend fun mkdir(path: String)
}
```

- 接口语义通用（乐观锁用 ETag 表达，不泄漏 WebDAV 特有概念）。
- 适配成本：WebDAV（首发，HTTP If-Match）、S3 兼容（If-Match）、GitHub Contents API（SHA 即 ETag + 限流策略）、Dropbox/OneDrive（rev/etag）——各约 200 行实现类，同步引擎/加密/合并逻辑零改动。
- 密文文件自包含（解密只依赖口令），整目录字节级可搬。
- **终极迁移路径**：本地是真相源，换云 = 新后端配置 + 从本地写全量快照，旧云端可弃。账单数据永不搬家。
- 保险：manifest 带 `repoVersion` 供格式演进；设置页可存多后端配置，一键切换激活。

### 7.2 信息架构（底部 4 tab + 中央记一笔）

```
┌──────────────────────────────────┐
│ 明细      图表     ⊕     预算      我的 │
└──────────────────────────────────┘
```

- **明细**：月收支结余卡（本位币）+ 按日分组列表（日小计）；下拉刷新 = 同步；同步状态角标（同步中/离线/失败）。
- **记一笔 ⊕**：ModalBottomSheet——金额大字 + 分类宫格 + 账户/日期/备注次级行；支出/收入/转账顶部切换；记住上次选择；**3 秒记完一笔**为目标；成功轻反馈（音效可关 + Snackbar 撤销）。
- **图表**：月/年切换；分类占比环形 + 收支趋势折线（Vico）；日历热力图后续。
- **预算**：月总预算进度条 + 分类预算列表，超支变红。
- **我的**：账户/分类管理、周期记账、模板、同步设置（后端配置/口令/状态）、备份与导出（CSV/JSON/加密备份文件）、应用锁（生物识别+PIN）、外观、导出诊断包。

## 9. 错误处理

### 9.1 同步层

| 故障 | 处理 |
|------|------|
| 网络不可用/超时 | 静默跳过，UI 角标"离线"；恢复联网 WorkManager 自动补同步 |
| ETag 冲突 | 拉取→合并→重推，最多 3 轮，仍冲突放弃本次会话并提示（防活锁） |
| 坚果云 503 限流 | 指数退避（1min→5min→30min），当天不再自动同步 |
| 口令错误 | manifest 校验失败明确报错，绝不拉错数据 |
| 云端文件损坏/篡改 | 跳过损坏分片回退上一可用快照；本地真相源可随时全量重建云端 |
| 设备时钟漂移 | 会话对时记录偏移，合并前校正；30s 模糊区 deviceId 决胜兜底 |

### 9.2 数据层

- 本地每日滚动备份 7 份；Room 损坏时引导恢复。
- 备份先写临时文件再原子 rename，防写一半崩溃。
- 删除保护：账户下有交易只能归档；分类软删除后历史照常显示。

### 9.3 其他

- 不接崩溃上报 SDK（隐私原则 + 自用）；本地滚动日志 + 手动导出诊断包。

## 10. 测试策略

**单元测试（JVM，同步引擎为重心）**
- LWW 合并确定性：乱序注入 1000 条随机变更，两台模拟设备分别合并，断言终态一致。
- 墓碑全生命周期：传播 → 30 天治理 → 物理清除。
- 多币种属性测试：任意金额 × 汇率 × 逆汇率 ≈ 原值（误差 ≤ 1 分）。
- 周期规则边界：1/31 + 月周期、闰年 2/29、跨年补 3 期。
- 加密往返、错误口令拒绝、密文篡改检测（GCM tag）。
- 预算进度计算（含外币折算）。

**集成测试**
- JVM 内嵌内存 WebDAV 模拟服务，跑真实同步会话：双设备并发写、断网重连、503 限流、分片损坏四类剧本。
- Room DAO 测试（Robolectric / instrumented）。

**UI 测试**
- Compose 测试覆盖"记一笔"全流程（含撤销）；3 秒目标的操作步数自动化度量。

**实机验收**
- v0.3 交付前：两台真机 + 真实坚果云账号实战同步一轮。
